## Candidate verification

From a clean checkout of the candidate commit:

```powershell
python -m venv .venv
.venv\Scripts\python -m pip install -e ".[dev]"
.venv\Scripts\python -m pytest
.venv\Scripts\ruff check .
.venv\Scripts\mypy src tests
.venv\Scripts\python -m pip_audit .
.venv\Scripts\python -m build
```

Install the generated wheel into a second, empty virtual environment and verify
the distribution version, import, and CLI rather than relying on the editable
source tree:

```powershell
.venv\Scripts\python -m venv .tmp\release-venv
.tmp\release-venv\Scripts\python -m pip install --disable-pip-version-check `
  (Get-ChildItem .\dist\agentloom-*.whl | Select-Object -First 1).FullName
.tmp\release-venv\Scripts\python -c `
  "import importlib.metadata as m; import agentloom; assert m.version('agentloom') == agentloom.__version__"
.tmp\release-venv\Scripts\agentloom --help
```

Before tagging, inspect the exact candidate commit and generated archives for
credentials, private evidence, unexpected files, and version drift. Run the
model-free quick start from a clean clone. Do not use ignored local AgentTeams
evidence as if it were part of the release archive.

The wheel smoke covers the installable Python package and CLI entry point only.
Repository-owned demo cases, Alembic configuration, deployment resources, and
competition evidence are distributed through the GitHub source release, not as
a standalone wheel application.

## Publish checklist

- [ ] Freeze and record the candidate commit SHA.
- [ ] Pass CI, local distribution build, isolated wheel smoke, dependency audit,
  and source/history secret scans on that commit.
- [ ] Record and upload the real public demo; verify its public URL.
- [ ] Confirm the repository is publicly accessible at the frozen commit.
- [ ] Create annotated tag `v0.1.0` and publish the GitHub Release from the same
  commit only after all prior checks pass.
- [ ] Complete the competition-page submission without local-only URLs.

## Rollback

Do not move or replace a published tag. If a pre-release check fails, discard
the draft candidate and prepare a new commit. If a defect is found after
publication, keep `v0.1.0` immutable, document the issue, and release a patched
version from a reviewed fix. AgentTeams deployment rollback continues to use
the pinned `v1.1.2` resources and the procedures in
[`windows-agentteams.md`](../deployment/windows-agentteams.md).
