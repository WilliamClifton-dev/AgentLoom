# Submission Package Signing with sigstore cosign

> Status: **script ready, not yet executed on a public release**. The
> Active goal lists "third-party digital signature" as a P3 follow-up;
> the wrapper script in `deploy/signing/sign-submission-package.ps1`
> is committed and the verification steps below are ready to run on
> any host with `cosign` installed.

This document explains how a second-host operator signs the
`AgentLoom v0.1.0` submission package with sigstore cosign and how a
reviewer verifies the signature before trusting the package.

## Why a third-party signature

AgentLoom's evidence-first model is, on its own, self-attested: every
`SkillInvocationEvidenceRecord` is written by the same code that
asserts the invocation succeeded. A reviewer can replay the test
suite to reproduce the evidence, but the reviewer has to trust that
the package they replayed is the same package the maintainer shipped.
A detached signature from a public transparency log (Sigstore /
Rekor) binds the package bytes to a verifiable identity and lets a
reviewer confirm with one command that the maintainer is who they
claim to be and that the package has not been modified in transit.

## Prerequisites

- `cosign` ≥ 2.0 on the signing host. Install from
  <https://docs.sigstore.dev/cosign/system_config/installation/>.
- The submission ZIP referenced in
  `docs/competition/submission-package-manifest.json` already
  produced by the public-main gate.
- One of:
  - **Keyless flow (recommended for public competitions):**
    `AGENTLOOM_COSIGN_KEY=keyless://`. The signer authenticates to
    Fulcio with an OIDC identity and the signature is logged in
    Rekor; no long-lived private key to manage.
  - **Keyed flow:** a `cosign.key` pair generated by
    `cosign generate-key-pair`. Keep `cosign.key` offline after
    signing; publish only `cosign.pub` alongside the package.

## Sign the package

```powershell
# From the project root on the second host:
$env:AGENTLOOM_COSIGN_KEY = "keyless://"
pwsh -File deploy/signing/sign-submission-package.ps1 `
    -PackagePath artifacts/competition/AgentLoom-submission-v0.1.0.zip
```

The script:

1. Resolves the package path either from the manifest or from the
   explicit `-PackagePath` argument.
2. Verifies `cosign` is on `PATH` (or respects `-CosignBin`).
3. Verifies `AGENTLOOM_COSIGN_KEY` is set to a real key path or the
   literal `keyless://`; an empty value fails closed with an
   actionable error.
4. Runs `cosign sign-blob` with the resolved key, the package path,
   and a `SignatureOut` / `CertificateOut` pair under
   `artifacts/signatures/`. The script **never** uses
   `Invoke-Expression`, so a malicious filename cannot inject
   PowerShell syntax.
5. Asserts the resulting signature is at least 64 bytes; a
   zero-byte or stub signature fails closed even if cosign
   returned exit 0.
6. Prints the exact `cosign verify-blob` command the reviewer will
   run.

## Verify the package

A reviewer with the same `cosign` version installed:

```bash
# 1. Inspect the signing certificate
cosign verify-blob \
    --signature artifacts/signatures/AgentLoom-submission-v0.1.0.zip.sig \
    --certificate artifacts/signatures/AgentLoom-submission-v0.1.0.zip.cert \
    artifacts/competition/AgentLoom-submission-v0.1.0.zip

# 2. (Keyless only) confirm the certificate's identity matches the
#    expected OIDC subject.
cosign verify-blob \
    --signature artifacts/signatures/AgentLoom-submission-v0.1.0.zip.sig \
    --certificate artifacts/signatures/AgentLoom-submission-v0.1.0.zip.cert \
    --certificate-identity "https://github.com/WilliamClifton-dev/AgentLoom/.github/workflows/release.yml@refs/tags/v0.1.0" \
    --certificate-oidc-issuer "https://token.actions.githubusercontent.com" \
    artifacts/competition/AgentLoom-submission-v0.1.0.zip
```

A passing verification prints `Verified OK` and the SHA-256 of the
package. A failing verification prints the mismatch reason and a
non-zero exit code; the script does not try to "soft-fail" missing
signatures.

## Tying the signature into the public surface

Once the signature exists:

1. Commit the signature and certificate under
   `artifacts/signatures/` and push the tag.
2. Add a `## Verification` section to
   `docs/competition/submission-operator-checklist.zh-CN.md` that
   links to `docs/security/signing-submission.md` and pastes the
   exact `cosign verify-blob` command.
3. Record the Rekor entry URL (or, for the keyed flow, the
   `cosign.pub` SHA-256) in
   `docs/competition/agentloom-preliminary-submission.md` so
   reviewers do not have to look it up.

## When to re-sign

- Every new `vX.Y.Z` GitHub Release tag.
- Every change to the contents of an existing release ZIP
  (re-publishing the same version with a different artifact
  requires a new tag).
- Never sign a package that has not been produced by the
  public-main gate's `build` job. The signature is meaningless
  without the reproducible build that produced the bytes it
  attests to.

## Known limits

- `cosign` is not bundled with the project. The first run on a
  fresh host requires an explicit install. The
  `deploy/signing/sign-submission-package.ps1` script refuses to
  run if `cosign` is missing.
- The script targets `cosign sign-blob`, not the in-toto
  attestation flow. The current submission is a single ZIP; if
  the project later ships a multi-artefact release, the script
  should grow a per-artefact `attest` step.
- The `--output-certificate` flag is only emitted when
  `AGENTLOOM_COSIGN_KEY` is a path (keyed flow). For the
  `keyless://` flow, the certificate is fetched from Rekor at
  verify time, so no `.cert` file is produced.
